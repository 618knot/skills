# AIアンチパターン（Gotchas #1–#10）と定量的監査基準

LLMが「解説アニメーションWeb UI」を自律生成する際、装飾の派手さやコードの簡潔さを優先した結果として陥りやすい認知科学的失敗パターンと、機械的・構造的に遮断するための MUST / NEVER 制約および自己監査基準を定義する。

---

## 1. 定量的エビデンス（なぜ「装飾モーション・無音同時字幕・一本道再生」が失敗するのか）

### 1.1 教育アニメーション vs 静的図解のメタ分析効果量

| 研究 | 条件・対象知識 | 効果量（95% CI / 有意性） | 設計への帰結（Hattie 教育的有意水準 `0.40` 基準） |
| :--- | :--- | :--- | :--- |
| **Höffler & Leutner (2007)** | 全体平均（26研究・76比較） | $d = 0.37$（`0.25–0.49`） | 全体平均は中程度にとどまり、無差別なアニメ化は不十分。 |
| | 表象的（Representational）アニメーション | $d = 0.40$（`0.26–0.53`） | 概念・現象の働きを直接表象する場合に教育的有意ライン到達。 |
| | 手続き・運動知識（Procedural-motor） | $d = 1.06$（`0.72–1.40`） | 手順・運動・ステップ遷移で最大級の効果。 |
| **Berney & Bétrancourt (2016)** | 全体平均（61実験・140比較・7,000名超） | $g = 0.226$（`0.12–0.33`, $p < .001$） | Castro-Alonso et al. (2019) も $g = 0.23$。 |
| | 知識次元別（事実 / 概念 / 手続き / 応用） | $g = 0.336 / 0.162 / 0.387 / 0.333$ | 知識次元間の差は非有意（$p = 0.28$）。 |
| | ペース制御・モダリティ（システム制御 / 音声併用 / **付随テキストなし**） | $g = 0.309$ / $g = 0.336$ / **$g = 0.883$** | 付随テキストなし（$g = 0.883$）と全体平均の乖離が、文字併用による視覚チャネル競合の深刻さを示す（※Table 3 に画面テキスト併用群の個別値は未収載）。 |
| **Ploetzner et al. (2020)** | 変化の単純特徴を学ぶ課題 | $g = 0.340$ | 変化そのものの理解で優位性が出現。 |
| | 変化の複雑特徴（加減速等）を学ぶ課題 | **$g = 0.647$** | 加減速・力学・軌道変化はアニメーションの本領。 |
| | **変化特徴が学習目標でない課題** | **$g = 0.043$** | 静的図解と無差。静的配置比較を無理に動かさない。 |

### 1.2 マルチメディア学習（Mayer CTML）・知覚・同期・関与の重要数値

- **Mayer & Fiorella 転移効果量中央値（CTML）**:
  - **Coherence（無関係詳細の排除）**: $d = 1.66$ ／ **Coherence（BGM・環境音排除）**: $d = 1.11$
  - **Multimedia（語と図の統合）**: $d = 1.35$
  - **Temporal Contiguity（時間的近接性）**: $d = 1.22$（動画研究 $d = 1.31$）
  - **Redundancy（重複テキスト排除）**: $d = 0.86$
  - **Pre-training（要素の事前導入）**: $d = 0.85$
  - **Segmenting（学習者ペース分割）**: $d = 0.67$
  - **Modality（画面文字より音声優先）**: $d = 0.65$
- **運動知覚と追跡容量**:
  - **動き vs 色（Bartram & Ware, 2002; Bartram et al., 2003）**: 動きの検出時間は近傍・周辺視野とも約 `1秒`・誤検出率ほぼ `0%`（色は近傍 `2.3秒`/`5.5%`、周辺 `4.6秒`/`24%`）。方向差のみで別群識別するには `90°` が必要。円運動は最も注意を奪う。
  - **MOT / FINST 上限（Pylyshyn & Storm, 1988; Cavanagh & Alvarez, 2005; Franconeri et al., 2010）**: 独立追跡上限は**約 `4個`**（左右視野各2個）。間隔過密や同一地点への**毎秒3回以上通過**で 4個未満でも崩壊。
  - **履歴保持の効果（IEEE TVCG 2025）**: 履歴（History）と軌跡（Trace）の保持が動的時系列タスク性能を **`1.49倍`** 改善。
- **時間同期・休止・字幕規格・関与**:
  - **待機マージン例**: AniVis（arXiv:2106.14313）ではマーク変化前に `500 ms`、データ関連ユニット前に `1000 ms` を採用。
  - **定着休止と能動的関与（Spanjers et al., 2012, 2016）**: `2秒` 程度の短い休止が分節・内省に有効。休止中に自由想起を促す能動的休止は転移成績を有意向上（$\eta^2 = 0.314, p = 0.019$）。一方、熟達者には固定休止が負担になる（Expertise Reversal）。
  - **放送字幕規格**: Netflix 公式日本語（標準上限 `4 CPS`・1行最大 `13` 全角文字・最小 `500 ms`／密集区分で上限 `7 CPS`・`16` 文字）、一般要件（最大 `2行`・最小 `833 ms`・最大 `7秒`）、英語（目標 `17 CPS`・上限 `20 CPS`・BBC `160–180 WPM` $\approx$ `15–18 CPS`・1行 `37–42` 文字）。

## 2. AIがやりがちな10大アンチパターン（Gotchas #1–#10）と MUST / NEVER 制約

### Gotcha #1: 全要素の同時移動・一斉稼働（Staging 違反・全体同時再生）
- **失敗の症状**: 最初のシーンからシステムの全部品・全ノードを一斉に動かし、「全体の動き」をそのまま再生する。
- **認知科学的敗因**: 領域初心者は APM Phase 1（イベント分解）で視覚的顕著性に注意を奪われて分解に失敗する（Lowe & Boucheix, 2008, 2016）。さらに人間の独立追跡上限は約 `4個` であり（Pylyshyn & Storm, 1988）、5個以上の独立運動は追跡が崩壊する。
- **厳格ルール**:
  - **MUST**: 1ビート内で稼働する主役を単一焦点（または相互作用する `1ペア`）に限定し、独立軌道で同時移動する対象は原則 `1〜2個`（絶対上限 `4個`）に収める。5個以上は Common Fate で単一グループとして動かす。
  - **NEVER**: 複雑なシステムの全部品を初回ビートから同時稼働させない。
- **修正パターン**: `A+B` ペアで相互作用を示した後、共通要素 `B` を残したまま `B+C` を追加稼働させる Compositional Build を組む。

### Gotcha #2: 字幕切替と主動作の同時発生（視覚チャネル渋滞）
- **失敗の症状**: キャプションが切り替わった `0 ms` 後に即座に図形アニメーションが走り出す。
- **認知科学的敗因**: 音声なし環境ではテキスト読解と図形追跡が単一の視覚チャネル上で正面衝突し（Modality Principle $d = 0.65$、無テキスト $g = 0.883$ との落差）、読んでいる間に重要な変化を見逃す。
- **厳格ルール**:
  - **MUST**: キャプション表示後、日本語 `4 CPS`・英語 `17 CPS` 基準の読解静止時間（Phase A）と `200–400 ms` の視線誘導（Phase B）を置いてから主動作（Phase C）を開始する。
  - **NEVER**: 新規キャプション出現とキャンバス上の主要モーションを同時発火させない。
- **修正パターン**: タイムライン関数で `phaseAEnd = calcReadingDwellMs(caption, lang)` を算出し、`t < phaseAEnd` の間はキャンバス変位を 0 に固定する。

### Gotcha #3: 装飾的バウンス・常時ループ・無意味なフェードの乱用
- **失敗の症状**: 背景パーティクルが常時漂う、数値ラベルが毎回バウンドして跳ねる（Squash & Stretch）、アイコンが待機中にずっと回転し続ける。
- **認知科学的敗因**: 動きは周辺視野からでも誤検出率ほぼ `0%` で強制的に注意を捕捉し（Bartram et al., 2003）、とくに円運動は最強の妨害刺激となる。無関係詳細の排除（$d = 1.66$）は最大級の効果を持ち、誇張は偽の物理質量・意図を錯覚させる（Heer & Robertson, 2007）。
- **厳格ルール**:
  - **MUST**: すべてのアニメーションに Shi et al. (2021) の8大物語戦略（`Emphasis`, `Concretization` 等）のいずれかの意図タグを対応づける。
  - **NEVER**: 背景の常時回転・浮遊パーティクル、根拠のないバウンス（Squash & Stretch）、装飾目的のテキスト移動を入れない。
- **修正パターン**: 待機中の要素は完全静止させ、注意を引く際は 1回限りの `400–600 ms` パルスまたは非関連要素のディミング（`opacity: 0.15–0.25`）を使う。

### Gotcha #4: 意味的対応のない要素間の無理なモーフィング
- **失敗の症状**: 全く別の概念や異なるデータ集合へ切り替わる際、見た目がかっこいいという理由で SVG パスを連続モーフィングさせる。
- **認知科学的敗因**: モーフィングは強力なオブジェクト同一性（Object Permanence）を錯覚させるため、スキーマが異なる要素同士を補間すると誤った因果・等価関係のメンタルモデルを形成する（Heer & Robertson, 2007; Thompson et al., 2021）。
- **厳格ルール**:
  - **MUST**: 状態遷移前に要素 ID の対応表（`enter` / `update` / `exit`）を定義し、同一エンティティ（`update`）のみ座標・形状を連続補間する。
  - **NEVER**: データや概念の対応関係がない SVG パス同士をモーフィングしない（共有構造なしは `350–500 ms` のディゾルブ／カットを使う）。
- **修正パターン**: ビート定義のオブジェクト辞書で ID 一致を検証し、未共有 ID は `exit`（フェードアウト）＋ `enter`（フェードイン）へ振り分ける。

### Gotcha #5: 過剰なカメラ移動と空間配置の反転（空間迷子）
- **失敗の症状**: カットごとに急激なパン／ズームを繰り返したり、前シーンで左にあった入力・右にあった出力を次シーンで上下や左右反転させたりする。
- **認知科学的敗因**: 急激なカメラ動作や配置反転（180°ルール違反）は視聴者の空間マップと Eye Trace を破壊し（Smith, 2012）、前庭障害のめまいを誘発する（WCAG 2.2 SC 2.3.3）。
- **厳格ルール**:
  - **MUST**: シーンを跨いでも主要エンティティの相対位置・座標軸の向きを維持し、カメラ移動中はデータ変形を止める（Staging）。
  - **NEVER**: 画面全体の激しい連続ズーム／回転や、理由のないレイアウト左右反転を行わない。
- **修正パターン**: SVG `viewBox` 遷移は `900–1400 ms`（大距離最大 `1800 ms`）の専用ビートまたは専用フェーズに分離し、`prefers-reduced-motion` 時は穏やかなフェードへ置換する。

### Gotcha #6: 「間（Pause）」と定着ホールドの欠如
- **失敗の症状**: 1つのアニメーションが終わった瞬間（`0 ms` 後）に次の変化やテキスト切替・画面消去が始まる。
- **認知科学的敗因**: 休止なき連続再生は揮発性（Transience）によるワーキングメモリ飽和を引き起こす。`2秒` 程度の短い休止と時間的キューが分節効果を生む（Spanjers et al., 2012; Mayer Segmenting $d = 0.67$）。
- **厳格ルール**:
  - **MUST**: すべてのビート末尾に最低 `1000 ms`（Peak および重要ビートは `1800–2500 ms`）の静止定着ホールド（Phase D）を組み込む。
  - **NEVER**: モーション終了後 `0 ms` で即座に次の変換や画面消去へ繋げない。
- **修正パターン**: 各ビートデータに `holdMs`（通常 `1000–1500`、Peak `1800–2500`）を必須プロパティとして持たせ、最小 `1000 ms` を下回らないようクランプする。

### Gotcha #7: 等速リニア移動と極端な速度設定（機械的・追跡不能）
- **失敗の症状**: CSS の `linear` で位置移動させる、あるいは `150 ms` の瞬間移動や `5000 ms` の間延びした遷移を作る。
- **認知科学的敗因**: 等速リニア移動は開始・終了の衝撃が強く不自然で予測困難（Lasseter, 1987; Chang & Ungar, 1993）。遷移が速すぎると追跡エラーが急増し、遅すぎると集中が切れる（Heer & Robertson, 2007）。
- **厳格ルール**:
  - **MUST**: 位置・サイズ・カメラ遷移には Cubic Slow-in / Slow-out を標準適用し、単段階遷移 `800–1250 ms`・多段階遷移 $\le 2000\text{ ms}$ に収める。
  - **NEVER**: 物体の位置移動やカメラ移動に `linear` イージングを使わない（定速信号の連続フロー表現など明確な物理理由がある場合を除く）。
- **修正パターン**: タイムライン関数内の補間に `easeInOutCubic` / `easeOutCubic` / `easeCamera` を標準組み込みし、物理的定速移動のみコメントで理由を明示する。

### Gotcha #8: 巻き戻し・一時停止・1ビート戻し不可の一本道再生
- **失敗の症状**: `setTimeout` の連鎖や CSS `@keyframes` 一発再生で、「今の変形をもう1回見たい」「速度を上げたい」が操作できない。
- **認知科学的敗因**: 巻き戻し・再再生できない受動視聴（例：XTango）はテキスト単独に優位性を示せない（Stasko et al., 1993; Hundhausen et al., 2002）。また固定ペースのみでは熟達者に外在的負荷がかかる（Expertise Reversal: Spanjers et al., 2011）。
- **厳格ルール**:
  - **MUST**: 決定論的タイムラインエンジンを構築し、「再生/一時停止・1ビート戻し/送り・再再生・チャプターシーク・速度変更（`0.5x–2.0x`）・手動ステップ切替」を必須実装する。
  - **NEVER**: `setTimeout` 連鎖や不可逆な CSS 一発アニメーションで巻き戻し不能な解説を作らない。
- **修正パターン**: `(beatIndex, elapsedMs)` から全SVG/Canvas状態を計算する純粋関数 `render(state)` に統一する。

### Gotcha #9: 定義・一般数式からの唐突な開始とテキスト過密
- **失敗の症状**: ビート1から長文の定義ボックスや抽象公式を貼り付け、画面下部に 3〜4行の解説パラグラフを字幕として流し続ける。
- **認知科学的敗因**: 初心者は具体例なしに抽象定義を統合できない（Sanderson 原則）。また 3行以上の長文字幕は図解領域を覆い、読解時間超過による視聴離脱を招く（Netflix 字幕基準）。
- **厳格ルール**:
  - **MUST**: 第1幕を具体例・直観的問いから開始し、定義・一般式は最終幕（Release）の到達点として色対応提示する。キャプションは最大 `2行`（日本語 $\le 32$ 全角文字、英語 $\le 84$ 文字）に厳格制限する。
  - **NEVER**: 解説冒頭で長文の定義ブロックや一般公式を画面に貼り付けない。
- **修正パターン**: 1〜3語の単語ラベルは図形直近へ移し、下部キャプションは 8〜16文字程度の極短フレーズへ要約する。

### Gotcha #10: アクセシビリティ無視と揮発性放置（reduced-motion・履歴欠如）
- **失敗の症状**: 大きなズームや回転が `prefers-reduced-motion: reduce` 環境でも強制再生される。また変化前の図形が跡形もなく消えるため前後比較ができない。
- **認知科学的敗因**: 前庭障害のある利用者にとって強制ズームや動きはめまい・吐き気・片頭痛の原因となり（WCAG 2.2 SC 2.3.3）、過去状態の消失は比較の短期記憶負荷を増大させる（IEEE TVCG 2025）。
- **厳格ルール**:
  - **MUST**: `prefers-reduced-motion: reduce` 自動対応＋手動「モーション軽減」トグルを実装し、変化比較が必要なビートでは直前状態の薄い残像（Trace/History：`opacity: 0.15–0.25`）を残す。
  - **NEVER**: モーション停止手段のない強制自動再生、または変化前の比較基準が跡形もなく消える設計を行わない。
- **修正パターン**: モーション軽減時はカメラ・軌道移動をスキップして「Before残像＋After静止図＋静的軌跡線」を `<= 200 ms` の穏やかなフェードで提示する。

## 3. 出力前 7項目自己監査ゲート（Self-Audit Gate）詳細基準

コード出力直前に全ビート・全スクリプトを以下で監査し、不合格サインが1つでもあれば該当ステージへ差し戻す。

| 監査項目 | 検査対象 | 不合格サイン（1つでも該当したら要修正） | 差し戻し先 |
| :--- | :--- | :--- | :--- |
| **監査1（無音同期）** | 全ビートのキャプション文字列と Phase A/C 時刻 | ・キャプションが 3行以上、または日本語 `> 32字` / 英語 `> 84字`<br>・`motionStartMs < calcReadingDwellMs(...) + phaseBMs` になっている | Stage 1 / Stage 3 |
| **監査2（Staging と追跡上限）** | Phase C の同時アニメ対象とディミング | ・独立軌道で同時稼働する対象が `5個以上` ある（Common Fate 化漏れ）<br>・非関連要素のディミング（`0.15–0.25`）がなく全要素が同じ輝度で競合 | Stage 3 / Stage 4 |
| **監査3（意味的対応）** | `enter / update / exit` 表とモーフィング処理 | ・ID対応のない別概念同士を形状モーフィングしている<br>・Timestep 2D移動を X→Y に直交段階化している、または Squash & Stretch がある | Stage 2 / Stage 3 |
| **監査4（間とイージング）** | 補間関数と Phase D (`holdMs`) | ・位置/サイズ/カメラ補間に `linear` が残っている（定速フロー等の明示的例外を除く）<br>・`holdMs < 1000`（Peakビートで `< 1800`）の箇所がある | Stage 3 / Stage 4 |
| **監査5（視覚衛生）** | CSS `@keyframes` / JS ループ | ・背景パーティクル、常時回転、装飾目的の無限パルス（`infinite`）がある<br>・物語戦略タグに紐づかない動きがある | Stage 3 / Stage 4 |
| **監査6（空間連続性と履歴）** | シーン座標・`viewBox`・残像レイヤー | ・前後のビートで同じ概念の左右/軸向きが反転している<br>・変化比較ビートで直前シルエットや軌跡（Trace/History）が残っていない | Stage 2 / Stage 4 |
| **監査7（制御性とアクセシビリティ）** | タイムラインエンジン・UIコントロール・a11y | ・`setTimeout` 連鎖でシーク/1ビート戻しが壊れる<br>・速度切替/手動ステップ/`prefers-reduced-motion` 自動検知＆手動トグルのいずれかが欠けている | Stage 4 |

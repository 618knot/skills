# 5大図解パターン・認知科学的根拠・アンチパターン集

本リファレンスは、`animated-diagram` スキルが生成する「ドキュメント挿絵型アニメーション構成図・フロー図」の認知科学的裏付け、5大図解パターンの具体設計仕様、およびAIがやりがちな10大アンチパターン（Gotchas #1–#10）を定義する。

---

## 1. 挿絵フォーマット向け 運動知覚・認知負荷・WCAG 2.2 定量根拠

| 領域・文献 | 定量的知見・認知制約 | 挿絵フォーマット（`animated-diagram`）への設計ルール |
| :--- | :--- | :--- |
| **多重物体追跡（MOT / FINST）**<br>Pylyshyn & Storm (1988), Cavanagh & Alvarez (2005), Franconeri et al. (2010) | 人間が独立軌道で同時追跡できる移動対象の上限は **`<= 4個`**（左右視野各2個）。間隔が狭い箇所や同一地点への **毎秒3回以上の通過** で 4個未満でも追跡が崩壊する。 | 基本は **1波あたり 1〜2トークン** を順番に流す。ファンアウト並列でも独立軌道は **`<= 4`** に抑え、5以上の並列集合は同一位相・同一速度で動かす **Common Fate** グループにまとめる。 |
| **周辺視野の運動捕捉**<br>Bartram & Ware (2002), Bartram et al. (2003) | 動きは周辺視野からでも約 `1秒`・誤検出率ほぼ `0%` で強制的に注意を奪う（色変化は近傍 `2.3秒/5.5%`・周辺 `4.6秒/24%`）。特に円運動は最強の注意妨害刺激。 | 記事本文を読んでいる読者の周辺視野を常時ハイジャックしないよう、**全矢印の点線行進（Marching Ants）や待機スピナーの常時回転を禁止**し、1波完了ごとに **`1200–1800 ms` の完全静止休止（Rest Dwell）** を設ける。 |
| **内部連続キューと履歴効果**<br>Boucheix & Lowe (2010), IEEE TVCG (2025) | 外部から指す静止矢印よりも、パス内部に沿って色が連続伝播する **Progressive Path** が低顕著・高関連領域への視線誘導に優れる。直前軌跡・履歴の保持は動的課題性能を **`1.49倍`** 改善する。 | 信号トークンの移動と厳密同期してエッジ自体を **Progressive Path** で発光させ、1波の完了までは通過済みエッジに控えめな点灯履歴を残してから、Rest Dwell 後に静かにリセットする。 |
| **Static-First と把握可能性**<br>Tversky et al. (2002), Robertson et al. (2008), Heer & Robertson (2007) | 読者が自力で構造を比較・把握するタスクでは、受動的な連続アニメより空間展開された静的表現が優位（Robertson 2008: Small Multiples `45.69s` vs 動くチャート `83.10s`）。状態遷移は `300–600 ms` 程度の滑らかな加減速（Cubic Slow-in/Slow-out）が適切で、誇張バウンス（Squash & Stretch）は誤った物理質量を錯覚させる。 | 箱・配線・番号ラベル（`①`, `②`）・役目はすべて静止画状態で100%読解できる **Static Backbone** として固定し、アニメは「順序と流れの直観化」の補助に徹する。状態／シナリオ切替時の遷移は **`300–600 ms`（Cubic）** とし、バウンス演出を禁止する。 |
| **注意分割排除と簡潔性**<br>Chandler & Sweller (1992), Mayer & Fiorella (CTML), Tufte (1983) | 離れた凡例ボックスや操作パネルは視覚探索（Split-Attention）を増大させる（Aligning $d = 0.48$）。不要な装飾・動画枠の排除（Coherence $d = 1.66$）、図から明らかな重複説明の排除（Redundancy $d = 0.86$）。 | 独立凡例ボックス（Legend）とスライダーパネルを廃止し、**直近ラベル＋インライン `<figcaption>` 1行** に統合する。動画プレイヤー枠・下部字幕ボックスは置かない。 |
| **アクセシビリティ**<br>WCAG 2.2 (SC 2.2.2, 2.3.3, 1.4.3, 1.4.11, 2.5.8) | SC 2.2.2（自動動作の停止/非表示）、SC 2.3.3（モーション軽減尊重）、SC 1.4.3（テキストコントラスト `>= 4.5:1`）、SC 1.4.11（UI部品・図形境界 `>= 3:1`）、SC 2.5.8（最小ターゲット `24×24px`）。 | `⏸ 停止 / ▶ 再開` ボタン（`<button type="button">`）、`min-block-size: 24px`・`min-inline-size: 24px`、文字コントラスト `>= 4.5:1`、SVG `font-size >= 12`、`prefers-reduced-motion: reduce` 時の静的矢印＋番号表示フォールバックを標準装備する。 |

## 2. 頻出5大図解パターンの詳細設計＆信号ルーティング仕様

すべてのパターンで、基本のキャンバス座標系は **`viewBox` 幅 `620〜720`、高さ `190〜330`** を目安とし、実際のチャット／記事カラム幅（約 `600〜760px`）で縮尺比 `~1.0` に近くなるよう設計して SVG 内文字（`font-size="12"` 以上）の視認性を担保する。

### パターン 1: システム構成・リクエスト往復図（Request-Response Topology）

- **構造と用途**: Client / Edge / API Gateway / Cache / Primary DB などの固定ノード間で、リクエストの経路分岐・フォールバック・応答返却を明快に比較する。
- **推奨 `viewBox` と総高さ**: `viewBox="0 0 680 220"`〜`"0 0 700 280"`（`<figure>` 全体の高さ `260〜340px`）。
- **レイアウト＆配線ルール**:
  - 3〜4ノードなら横1列配置（中央高さ `y = 105` 前後）。5〜6ノードなら **2段グリッド**（上段メインパス・下段 DB / Fallback / Sidecar）にして1ノード幅 `110–136px` を確保し、横潰れを防ぐ。
  - **往路・復路の平行オフセット分離**: 同一ノード対を結ぶ往路（リクエスト）は `y - 10`（実線レール＋往路色 `--primary` / `--chart-1`）、復路（レスポンス）は `y + 10`（破線または別色 `--success` / `--chart-2`）に分離して矢印とラベルの衝突をゼロにする。
  - エルボー配線は角丸（`Q` ベジェまたは半径 `8–10px` の円弧）にし、角でのトークン移動が滑らかに見えるようにする。
- **1波タイムラインとピル例**:
  - 往路ホップ1（`550 ms`）→ 往路ホップ2（`550 ms`）→ 処理ノード枠強調（`300 ms`）→ 復路ホップ群（各 `500 ms`）→ **`1500 ms` Rest Dwell**。
  - ピル例：`Cache Hit` / `Cache Miss`、`正常系` / `Circuit Open`。非選択側の経路は完全消去せず `opacity: 0.22` の薄い破線コンテキストとして残す。

### パターン 2: 非同期キュー・ワーカー並列パイプライン図（Async Queue & Worker Fan-out）

- **構造と用途**: Producer がタスクを投入して即座に `202 Accepted` を受け取り、裏側で Broker/Queue がバッファリングして複数ワーカーへ並列分配・永続化（または失敗時 DLQ 退避）する非同期性を表す。
- **推奨 `viewBox` と総高さ**: `viewBox="0 0 680 240"`〜`"0 0 700 290"`（総高さ `280〜350px`）。
- **レイアウト＆配線ルール**:
  - 左から `[Producer]` → `[Queue (可視スロット 3〜4枠)]` → 分岐 `[Worker 1]` / `[Worker 2]` / `[Worker 3]` → `[Store]`（下段右に `[Dead Letter Queue]` を配置可）。
  - Queue ノードの内部には **3〜4個の矩形スロット** を描き、投入時にスロットが1つ点灯→ワーカー引き取り時に消灯することで「バッファリングの decouple」を視覚化する。
- **1波タイムラインとピル例**:
  - 前半（同期境界）：Producer → Queue（`500 ms`）＋ Producer への `202 ACK` 返却（`400 ms`、Queue 投入直後に分岐）。
  - 後半（非同期処理）：Queue → Worker 1〜3 並列 Fan-out（同時稼働トークン `<= 3`、各 `600 ms`、`80–120 ms` の微小な分配オフセットまたは Common Fate 同時移動）→ Store 書込（`450 ms`）→ **`1500 ms` Rest Dwell**。
  - ピル例：`正常処理 (並列)` / `リトライ → DLQ`。

### パターン 3: シーケンス図・縦タイムライン（Vertical Sequence / Protocol Handshake）

- **構造と用途**: OAuth 2.0 / PKCE、TLS 1.3 ハンドシェイク、分散ロック取得、2相コミットなど、**時刻順の往復と各アクターの待機区間**が本質となるプロトコル解説。
- **推奨 `viewBox` と総高さ**: `viewBox="0 0 680 260"`〜`"0 0 680 320"`（総高さ `300〜380px`）。
- **レイアウト＆配線ルール**:
  - 上部 `y = 14..52` にアクター箱を **3〜4列**（例：`x = 95, 275, 455, 600`）固定し、下方向へ破線ライフラインを伸ばす。
  - メッセージ段数は **3〜6段** に厳選し、段ピッチを **`38–44px`** に取る（これ以上段数を増やすと `380px` を超えるため、細粒度は統合して表現する）。
  - 各メッセージ矢印の `10px` 上に固定ラベル（`① GET /authorize`、`② 302 code=...`）を置き、受信側ライフライン上には薄いアクティベーション矩形（幅 `10px`）を常時配置する。
- **1波タイムラインとピル例**:
  - 段 `i = 1..N` を上から順次実行（横移動 `450–550 ms` ＋ 次段開始前小休止 `150 ms`）。完了済み段のエッジは1波終了まで点灯色を維持（Snowballing 履歴）し、全段完了後に **`1500 ms` Rest Dwell** を置いて先頭へ戻る。
  - 自己呼び出し（トークン検証等）は右へ `28px` 膨らむ角丸 U 字パスで描く。
  - ピル例：`新規ログイン (PKCE)` / `Refresh Token 更新`。

### パターン 4: ステートマシン・状態遷移図（State Machine & Lifecycle）

- **構造と用途**: Circuit Breaker（`Closed` / `Open` / `Half-Open`）、WebSocket / TCP 状態、Saga 補償、ジョブステータス遷移など、**現在状態（Current State）と遷移条件（Guard / Event）** の解説。
- **推奨 `viewBox` と総高さ**: `viewBox="0 0 680 220"`〜`"0 0 680 270"`（総高さ `260〜330px`）。
- **レイアウト＆配線ルール**:
  - 状態ノードは **3〜5個** の角丸矩形またはピル（幅 `120–145px`、高さ `52–60px`）とし、内部に「状態名（太字 `13px`）」と「不変条件／振る舞い（例：`失敗率を計測`、`12px`）」を2行で固定表示する。
  - 左端に初期状態マーカー（`●→`）を置く。双方向遷移は上下に大きく弧を膨らませた2次ベジェ（`Q`）で分離し、自己遷移はノード上辺の外側ループで描く。ガード条件ラベル（`失敗 >= 5回`、`30s経過` 等）は各弧の中点直近に背景抜きまたは小ピルで固定配置する。
- **1波タイムラインとピル例**:
  - 選択中シナリオの遷移経路（例：`Closed → Open → Half-Open → Closed`）に沿って 1ステップずつ信号トークンが遷移弧を走り（`550 ms`/遷移）、到達と同時に遷移先状態ボックスの枠線太さ・背景ティントを `350 ms` でアクティブ化（直前状態は `400 ms` 後に標準色へ戻す）。1周後に **`1600 ms` Rest Dwell**。
  - ピル例：`障害発生 → 自動復旧` / `プローブ失敗 → 再Open`。

### パターン 5: データ/パケット変換パイプライン図（Data / Packet Transformation Pipeline）

- **構造と用途**: コンパイラ工程、HTTP/TLS カプセル化、RAG チャンク化→埋め込み→検索、ETL 変換など、**処理ステージを通過するたびにデータ構造や表現形式が変容する過程**の解説。
- **推奨 `viewBox` と総高さ**: `viewBox="0 0 680 230"`〜`"0 0 720 280"`（総高さ `270〜340px`）。
- **レイアウト＆配線ルール**:
  - ステージ数は **3〜4段** に絞る。上段（`y = 24..92`）に変換ステージ箱を左から右へ水平配置してパイプライン矢印で結ぶ。
  - 下段（`y = 122..214`）に、各ステージ直下と縦線で緩く対応付けた **Static-First 具体データスナップショット枠**（モノスペース `12px`、1〜2行のJSON断片・ASTツリー・ベクトル数値・パケットヘッダ）を常時並置する。
- **1波タイムラインとピル例**:
  - 1個のパケットバッジ（初期形状/色 `--chart-1`）が左から右へステージを通過し（各ホップ `550 ms`）、各ステージ箱を通過する瞬間にバッジ内の短い型ラベル（例：`Raw` → `Tokens` → `AST` → `Bytecode`）とセマンティック色が切り替わり、直下のスナップショット枠の枠線が連動ハイライトされる。全段通過後に **`1500 ms` Rest Dwell**。
  - ピル例：`有効ペイロード` / `バリデーション拒否`。

## 3. AIがやりがちな10大アンチパターン（Gotchas #1–#10）

| # | アンチパターン（やりがちな失敗） | 認知科学的・技術的敗因 | MUST / NEVER 修正ルール |
| :--- | :--- | :--- | :--- |
| **1** | **クリスマスツリー点線行進（Marching Ants）** | 全エッジの `stroke-dashoffset` を常時アニメーションさせると、周辺視野の運動検出が休まる暇なく発火し、記事の文章が読めなくなる（Bartram & Ware, 2002）。 | **NEVER**: 常時無限ループする点線矢印や常時回転スピナー。<br>**MUST**: 1トランザクションを順次流した後、`1200–1800 ms` の完全静止休止を挟む。 |
| **2** | **動画プレイヤーUI・下部字幕の混入** | 挿絵なのにシークバー・倍速・前後ビートボタン・字幕枠を付けると、記事の流し読み（Skimming）を遮断し、重複情報で冗長負荷が増える（Mayer Redundancy $d = 0.86$）。 | **NEVER**: シークバー・速度選択・Phase A 字幕読解待ち。<br>**MUST**: `<figure>` ＋1行 `<figcaption>` ＋ヘッダー右上の小ピル＆停止ボタンのみ。 |
| **3** | **静止画で意味が通じない（Transience）** | 矢印やステップ番号をアニメーション出現に依存させると、スクリーンショットや初見時に「どこからどこへ・何番目か」が読めない（Apprehension 違反）。 | **NEVER**: ホバーやアニメ到達までラベル・矢印を隠す覗き穴設計。<br>**MUST**: 箱・レール・矢印頭・番号ラベル（`①`, `②`）を常時固定表示する。 |
| **4** | **縮小 `viewBox` による `12px` 割れ** | `viewBox="0 0 1200 400"` 内に `font-size="12"` を置くと、600px幅コンテナでは実効 `6px` に潰れて判読不能になる。 | **NEVER**: 横幅 `> 800` の `viewBox` に小さいフォントを詰める。<br>**MUST**: `viewBox` 幅を `620–720` に設計し、全 SVG テキストを `>= 12`（推奨 `12–13`）にする。 |
| **5** | **独立凡例ボックス・スライダーパネル** | 図の下や横に凡例ボックスやスライダーを並べると、視線往復（Split-Attention）と縦幅肥大（`> 450px`）を招く。 | **NEVER**: 別枠 Legend ボックスや複数スライダー。<br>**MUST**: 線・ノードの直近に直接役割テキストを置き、1行 `<figcaption>` で要約する。 |
| **6** | **往復線の衝突＆同時追跡上限超過** | 双方向矢印を1本の線に重ねたり、5個以上の独立パケットを同時に走らせたりすると（MOT `> 4`）、衝突と追跡崩壊が起きる（Pylyshyn & Storm, 1988）。 | **NEVER**: 往路と復路を同一座標に重ねる、または独立移動 `>= 5`。<br>**MUST**: 往路・復路は `±8〜10px` 以上オフセット分離し、同時独立移動 `<= 4` に制限する。 |
| **7** | **雑な `0.01ms` 一括リセットでの reduced-motion 対応** | `* { animation-duration: 0.01ms !important }` を書くと、矢印のハイライト状態が中途半端に消えたり遷移が壊れて読解不能になる。 | **NEVER**: CSS一括ワイルドカードでの雑な時間短縮。<br>**MUST**: `prefers-reduced-motion: reduce` 時は `.is-static` 状態へ切り替え、移動パケットを隠して**色付き矢印＋番号ラベル**の完成図を静止描画する。 |
| **8** | **`:root` 色定義・外部CDN依存・コントラスト不足** | `:root` に `--bg` や `--card` をハードコードするとホストテーマと衝突し、Tailwind CDN 等の外部読み込みは Claude Artifacts の CSP 制限やオフライン環境でブロックされる。薄色バッジ＋白文字も `4.5:1` 未満を招く。 | **NEVER**: `:root` へのローカル色定義、Tailwind CDN 含む外部 `<script>`/`<link>` 読み込み、低コントラスト配色。<br>**MUST**: 標準 `<style>`（Vanilla CSS）に統一し、ホスト変数を要素スタイルで直接参照（`light-dark()` フォールバック併用）＋文字コントラスト `>= 4.5:1` を満たす。 |
| **9** | **`100vh` / `height: 100%` によるフレーム崩壊** | Claude Artifacts や `<agent-embed>`、記事埋め込み環境では親から高さが渡されないため、`100vh` / `height: 100%` を指定すると高さ0や極小スリバーに潰れる。 | **NEVER**: トップレベルコンテナへの `100vh` / `min-h-screen` / `height: 100%`。<br>**MUST**: コンテンツ高（`220〜380px` 目安）主導の自然なフロー配置＋適度な上下 `padding` にする。 |
| **10** | **`<div role="button">` 濫用＆ `user-select: none` 汚染** | 非ネイティブボタンはキーボード操作やフォーカス輪郭が欠落し、コンテナ全体に `user-select: none` を書くと技術用語や `<figcaption>` がコピーできなくなる。 | **NEVER**: `<div>` のクリックボタン化、図内テキスト／キャプションへの `user-select: none`。<br>**MUST**: `<button type="button">`＋`aria-pressed`＋`:focus-visible`＋`min-block-size: 24px` を使い、`user-select: none` はボタンUIのみに限定する。 |

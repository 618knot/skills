# Obsidianログ出力仕様

全問終了後に、今回の対話結果を Obsidian で検索・集計・知識リンクしやすい Markdown ファイル（`.md`）として保存するための規約とテンプレート。

---

## 1. 保存先とファイル名の解決ルール（ハードコード禁止）

保存先パスやファイル名規則をスキル内に固定してはならない。以下の優先順位で解決する：

1. **実行時のユーザー指定**：会話の開始時または終了時にユーザーが明示したディレクトリ／ファイルパス
2. **環境変数**：`PRE_REVIEW_QUIZ_LOG_DIR`（ファイル名規則は任意で `PRE_REVIEW_QUIZ_FILENAME_TEMPLATE`）
3. **設定ファイル**（上から最初に見つかったものを使用。雛形は `../config.example.yaml`）：
   - リポジトリ直下：`.pre-review-quiz.yaml`
   - リポジトリ内設定：`.agents/pre-review-quiz.yaml`
   - ユーザーグローバル：`~/.config/pre-review-quiz/config.yaml`
4. **未設定時のフォールバック**：
   - `save_behavior: skip` の場合は保存せず終了する。
   - 保存先が未指定（または `save_behavior: ask`）の場合は、ユーザーに「保存先パス（Obsidian Vault内のフォルダ等）を指定しますか？ スキップまたはチャットへのMarkdown出力も可能です」と尋ねる。
   - 保存先が現在のワークスペース外（Obsidian Vault 等）で権限上直接書き込めない場合は、その旨を正直に伝え、コピー可能な完成版 Markdown 全文をチャットへ出力するか、書き込み先変更を提案する。

### デフォルトのファイル名規則と重複回避
- **デフォルトテンプレート**：`{{date}}_{{type}}-{{id_or_slug}}.md`
  - PRあり：`2026-11-24_pr-142.md`
  - PR未作成ブランチ：`2026-11-24_pr-fix-token-refresh.md`
  - Issue：`2026-11-24_issue-87.md`
  - ローカルDoc／メモ：`2026-11-24_doc-auth-library-comparison.md`
- **スラッグ化**：英数字とハイフン（または安全なファイル名文字）に正規化し、長すぎる場合は簡潔に切り詰める。
- **上書き防止**：同名ファイルが既に存在する場合は上書きせず、`-2.md`, `-3.md` と連番を付与する。

## 2. Obsidian 記法ルール（Frontmatter / Wikilink / タグ / Callout）

### YAML Frontmatter（必須プロパティ）
Dataview や Obsidian Properties で検索・集計できるよう、以下のキーをすべて出力する：

```yaml
---
date: 2026-11-24
type: pr # pr | issue | doc
repo: owner/repo # リポジトリ外ドキュメントなら ""
target_number: 142 # PR番号またはIssue番号（ブランチのみ・docの場合は null）
title: "トークンリフレッシュ時の競合解消とリトライ制御"
url: "https://github.com/owner/repo/pull/142" # PR/Issue URL、ローカルファイルなら相対パス、なければ ""
total_questions: 4
first_try_correct: 3
tags:
  - review-quiz
  - pr
  - owner-repo
  - oauth2
  - concurrency
---
```

- `tags` には `#` を付けず小文字ケバブケースで記述し、必ず `review-quiz`、モード（`pr` / `issue` / `doc`）、リポジトリ識別名（ある場合）、主要技術トピック（1〜4個）、設定の `default_tags` を含める。

### Wikilink（`[[...]]`）とタグ（`#...`）
- 再利用性の高い技術概念・仕様・パターン・ライブラリ名には **`[[...]]`** を付与し、他の技術ノートとリンクできるようにする（例：`[[OAuth2]]`, `[[リフレッシュトークン]]`, `[[楽観的ロック]]`, `[[N+1問題]]`, `[[トランザクション分離レベル]]`）。
- 今回のPR・Issueにしか存在しない一時的な変数名やローカルファイル名は Wikilink にしない。
- 各問題の末尾および全体の `## 関連トピック` に `[[...]]` をまとめる（必要に応じて本文中に `#...` タグを補助的に添えてもよい）。

### Callout 記法
視認性を高めるため、Obsidian 標準の Callout を活用する：
- 問題文：`> [!question]`
- 解説と根拠：`> [!note] 解説・根拠`
- 途中で見つかった要確認事項（該当時のみ）：`> [!warning] 要確認事項`

# 【Layer 2 共通】6フェーズ別ビジュアル規約・Focus+Context ＆ 10大アンチパターン

本ドキュメントは、Mode A（無音 HTML/SVG シアター）と Mode B（音声ナレーション付き MP4/WebM 動画）に共通する 6フェーズのビジュアル語彙、Focus+Context・Baum Principle 5 同時表示レイアウト、1080p 可読性基準、および PR 解説動画で AI が陥りがちな **10大アンチパターン（Gotchas #1–#10）** を定義する。

> [!NOTE]
> **エビデンス確度の明記**：コード表示における「1画面 10–15行推奨（上限18行）・28–32 px」といった数値は、査読付き実験による統計値ではなく、**1920×1080p 解像度・GitHub インラインプレイヤー縮小率（幅約 800 px ≒ 0.42倍）・WCAG 1.4.3（コントラスト比 4.5:1）・Legibility.info のスマホ視認性基準**から導出した設計推奨値である。

## 2. 画面レイアウト・Focus+Context・Baum Principle 5 ルール

### 2.1 2ペイン同期レイアウト（図 × 抜粋コード）と分割比較（`split_code`）
1. **標準 2ペイン（Mode A / B 共通）**:
   - 左ペイン（55–60%幅）：抽象アーキテクチャ／実行フロー SVG（Before 残像は破線 `opacity: 0.20–0.24` で保持、新経路は Progressive Path）。
   - 右ペイン（40–45%幅）：焦点コード抜粋（上部 `path/to/file.ext:L42-L50` 位置バッジ必須）。
2. **関連2変更点の同一画面同時提示（Baum Principle 5 準拠：`split_code`）**:
   - 「呼び出し元の引数追加」と「呼び出し先の定義変更」、または「変更前メソッド」と「変更後メソッド」が別ファイル・別行に離れている場合は、ビートを切り替えて記憶に頼らせるのではなく**左右2分割パネル（各パネル 12行以内）で同一フレームに同時表示**し、結ぶ矢印または共通 `data-key` で接続する。
3. **空間近接アンカーラベル（Spatial Contiguity $d = 0.79$）**:
   - 画面上には音声や下部キャプションの長文を繰り返さず、図・コードの直近に **`2〜3語` の短いキーワードバッジ**（例：`コミット後削除` / `非同期ロック`）だけを配置する。

### 2.2 コード抜粋と Magic Move 風差分の視認性ルール
- **非注目行のディミング**: 変更・注目すべき 1〜4行のみ不透明度 `1.0` ＋左端カラーライン（追加＝エメラルド、削除＝ローズ、リスク注意＝アンバー、焦点＝スカイ）とし、周囲の文脈行は `opacity: 0.35–0.38` へ後退させる。
- **1080p 画素幾何学基準（Mode B）**: 等幅フォント **`28–32 px`**（行間 `1.5倍` ＝ `42–48 px/行`、GitHub 幅約 `800 px` 縮小表示時も実効 `12–13 px` を確保）、見出し `48–60 px`、アンカーラベル `36–44 px`、コントラスト比 **`>= 4.5:1`**（WCAG 1.4.3）。
- **双方向 `data-key` 連動**: 左ペインのノード/エッジ、アンカーキーワード、右ペインの対応コード行に同一 `data-key` を付与し、タイムライン同期点灯（Mode B では発話の `50–100 ms` 先行）およびマウスホバー連動（Mode A）を行う。

## 3. PR解説動画・シアター 10大アンチパターン（Gotchas #1–#10）と MUST / NEVER 制約

| # | 失敗パターン（Gotcha） | 認知科学的・技術的敗因と一次ソース | SKILL に課す MUST / NEVER 制約 |
| :--- | :--- | :--- | :--- |
| **1** | **生 diff の丸映し・縦スクロール実況** | 全体文脈欠落＋全画面移動が視覚追跡を阻害。無関係行が認知負荷を増大（Coherence 原則、*CodeTube* の TL;DW）。 | **NEVER**: 生の `git diff` 塊やエディタの縦スクロールをそのまま映さない。<br>**MUST**: 抽象図と抜粋コード（Mode A $\le 12$行、Mode B 10–15行・上限18行）を往復する。 |
| **2** | **Git ファイル名アルファベット順の羅列** | 論理的結合がディレクトリ越しに寸断され分散計画（Delocalized Plans）を生む（Baum et al., 2017, 2019）。 | **NEVER**: ファイルパス順でシーンを並べない。<br>**MUST**: 依存・データフロー順に最大3クラスタへ再配列し、冒頭で順序規則を明示し、関連2箇所は同一画面に同時提示する。 |
| **3** | **長文テロップ焼き込み ／ 字幕と動きの同時衝突** | **Mode B**: 音声と同一の長文テロップは高速進行時に注意分割（Redundancy 原則）。<br>**Mode A**: 字幕変更と動きの同時発火は単一視覚チャネル上で衝突（Berney & Bétrancourt, 2016）。 | **Mode B MUST/NEVER**: 長文テロップ焼き込み禁止。2–3語アンカー＋分離 WebVTT。<br>**Mode A MUST/NEVER**: 日本語 `4.0 CPS`/英語 `17 CPS` の Phase A 読解静止完了前にモーションを開始しない。 |
| **4** | **尺の肥大化と結論の後回し（焦らしすぎ）** | 視聴維持中央値は最大6分で頭打ち（0–3分が最高維持75%・行動率56%：Guo et al., 2014）。PRレビューは冒頭で理由とリスクの即答が必要（Tao I-1, I-9; Wise et al., 2009）。 | **NEVER**: 300秒（5分）超の単一PR動画や、冒頭に結論がないサスペンス導入を作らない。<br>**MUST**: 冒頭 `10–15秒` で BLUF（目的・結論・影響範囲・不変条件）を提示し、標準 `60–180秒` に収める。 |
| **5** | **映像尺先行（Video-First）または決定論制御の欠如** | **Mode B**: 固定フレーム尺にTTSを押し込むと音声切れ・`45 ms` 超音声先行の同期ズレが生じる（ITU-R BT.1359-1）。<br>**Mode A**: `setTimeout` 連鎖では巻き戻し・1ビート戻しが不能（Hundhausen et al., 2002）。 | **Mode B MUST**: TTS先生成＋タイムスタンプ取得からフレーム算出（Audio-First）、視覚遷移は発話 `0–100 ms` 先行。<br>**Mode A MUST**: 単一状態 `tMs` の純粋関数 `render(state)`＋シーク/戻し/速度/`prefers-reduced-motion` 対応。 |
| **6** | **文字が小さすぎる・行数過多・低コントラスト** | GitHub PR インラインプレイヤー（約0.42倍縮小）やスマホ画面で文字が潰れて読めない（Legibility.info / WCAG 1.4.3）。 | **NEVER**: 1080p で `24 px` 未満のコード、19行以上の詰め込み、`80文字/行` 超、コントラスト比 `4.5:1` 未満を使わない。<br>**MUST**: 1080p でコード `28–32 px`・行間 `1.5倍`（Mode A は `12 px` 以上）、非注目行ディミングを徹底する。 |
| **7** | **Why を語らずコードの逐語朗読（What の実況）** | 開発者の最重要ニーズは「変更理由と却下案・トレードオフ」（Bacchelli & Bird, 2013; MacLeod, 2015; *Lacy*, 2026）。 | **NEVER**: 「3行目で変数 `x` に1を足します」のような構文逐語実況を書かない。<br>**MUST**: 音声／キャプションでは「なぜこの設計を選んだか・却下案とのトレードオフ」を会話調（Personalization $d=1.00$）で語る。 |
| **8** | **書き言葉原稿と記号・生パスの TTS 棒読み** | パス名、記号（`< > & 「」`）、長い camelCase/snake_case 識別子は SSML 破損や機械的棒読みを招き信頼感を損なう（Craig & Schroeder, 2019）。 | **NEVER**: TTS原稿に生パス・演算子・未展開識別子・句読点連打ポーズを含めない。<br>**MUST**: 自然な話し言葉へ置換し、ポーズは SSML `<break time="350ms"/>` または無音フレームで厳密制御する。 |
| **9** | **正常系ハッピーパスのみ・リスク＆類似箇所（I-10）隠蔽** | DB/認可/非同期/テスト書換/AI生成落とし穴や類似箇所の波及を隠すと重大バグを見落とす（Tao I-9, I-10）。 | **NEVER**: 周辺ファイルを読まずに推測したり、正常系だけで解説を終わらせない。<br>**MUST**: 周辺 1〜4ファイル実読の裏取りと正確な `file:line` バッジを付け、フェーズ⑤で高リスク・異常系・類似箇所一貫性を必ず検証する。 |
| **10** | **空間配置反転・残像欠如・配布規格違反** | Before/After で配置反転（180°ルール違反）や前状態の消失が起きると比較負荷が跳ね上がる（Smith, 2012; IEEE TVCG 2025 `1.49倍`）。また WebM/`yuv444p`/`10 MB` 超は GitHub PR 添付に失敗する。 | **NEVER**: 既存ノードの座標を理由なく反転させない。Mode B で `yuv444p` や `10 MB` 超のまま納品しない。<br>**MUST**: Before 経路を破線残像で保持し、Mode B は `H.264 yuv420p`・`+faststart`・**`<= 9.5 MB`**・冒頭5秒ミュート完結で出力する。 |
